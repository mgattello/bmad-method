# Integration specs

Run with `npm run test:int` from the repository root (it builds the contract first). Each spec
builds the real app with `buildApp` on a `SqliteTodoRepository` over a temp file created in
`beforeAll` (`mkdtemp`) and removed in `afterAll`, and drives it with `fastify.inject`; no
network port is opened.

| Spec                       | Proves                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `todos.int.test.ts` (GET)  | A fresh file yields `200 []`; rows seeded directly with better-sqlite3 come back newest first with exactly `id, description, completed, createdAt`; a second app on the same file sees the same order (restart persistence)                                                                                                                                                                                                                                                                                 |
| `todos.int.test.ts` (POST) | `201` with a trimmed Todo (UUID v4 `id`, millisecond ISO `createdAt`), durable for a second app and a direct better-sqlite3 read; two creates list newest first; `DESCRIPTION_MAX` and 1 character accepted; empty, whitespace or over-long after trim is `400 VALIDATION_ERROR` with the rule text and nothing inserted; wrong type, unknown field, malformed JSON and non-JSON bodies are `400 VALIDATION_ERROR` with the generic message; a closed store is `500 INTERNAL_ERROR` with one error log line |
| `health.int.test.ts`       | `200 { status: "ok" }` while the store is open, `503 { status: "degraded" }` after the repository is closed                                                                                                                                                                                                                                                                                                                                                                                                 |
| `not-found.int.test.ts`    | `404 { code: "NOT_FOUND", message }` for an unknown route and a trailing slash; `500 { code: "INTERNAL_ERROR", message }` with no library text once the store is closed                                                                                                                                                                                                                                                                                                                                     |

The runner has no `--passWithNoTests`, so a mis-globbed spec directory fails the run.
| `todos.int.test.ts` (PATCH) | `200` tick and untick durable for a second app and a direct better-sqlite3 read; description only and both fields; `id` and `createdAt` never change; rule violations are `400 VALIDATION_ERROR` with the rule text and the row unchanged; `{}`, unknown field, wrong types, malformed JSON and non-JSON bodies are `400` with the generic message; unknown id, `not-a-uuid`, `%20` and a trailing slash are `404 NOT_FOUND`; a closed store is `500 INTERNAL_ERROR` with one error log line |
